## GIT DAY 27

### CONVENTIONAL COMMITS
- Conventional commits help you understand the purpose of the code change without even opening them 
- The format of conventional commits are: ` <type>: <description>`

### COMMON COMMIT TYPES
1. feat:
- A new feature
2. fix:
- bug fxes
3. docs:
- documentation only
4. style:
- No logic changes Example: style: remove trailing whitespace
5. refactor:
- Improve code without changing the logic or behaviour
6. test:
- Testing
7. chore:
- maintainence work Example = Chore: upgrade packages
8. ci:
- CI/CD changes Example = ci: add GitHub Action workflow
9. perf:
- Performance improvements

## ATOMIC COMMITS
- Commiting a single commit that has lots of code changes is hard to review and also understand.
- Instead commiting every logical code changes makes it atomic commits, easy to understand and also review 

### WHY DO WE NEED ATOMIC COMMITS
- Easier debugging
- Easy to understand
- Better release notes
