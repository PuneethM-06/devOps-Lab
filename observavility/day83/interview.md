
# Interview.md — Day 83

## 1. What is Grafana Loki?

Grafana Loki is an open-source log aggregation system used to centrally collect, store, and query logs from applications and infrastructure.

It helps us investigate logs from multiple services, pods, containers, and servers from a central location.

---

## 2. Why do we need centralized logging?

In a distributed application, logs can be generated by multiple services, pods, and servers.

Without centralized logging, we may need to manually check logs from each individual source.

With centralized logging:

    Multiple Applications / Pods / Servers
                    ↓
              Log Collection
                    ↓
                Grafana Loki
                    ↓
              Search and Filter

This makes troubleshooting and debugging easier.

---

## 3. How do logs reach Grafana Loki?

The general flow is:

    Application / Pod / Server
            ↓
        Generates Logs
            ↓
    Log Collector / Agent
            ↓
        Grafana Loki
            ↓
          Grafana

The application generates logs, a collector or agent gathers and forwards them to Loki, and Grafana can then be used to query and investigate them.

---

## 4. What are labels in Loki?

Labels are key-value pairs attached to log streams that help identify and organize logs.

Examples:

    service="payment-service"
    environment="production"
    namespace="default"

Labels are used to select relevant log streams.

Example:

    {service="payment-service", environment="production"}

---

## 5. What is a log stream?

A log stream is a collection of log entries that share the exact same set of labels.

Example:

    {service="payment-service", environment="production"}

    INFO Payment started
    INFO Validating card
    ERROR Payment failed

If the label set changes, Loki treats it as a different log stream.

---

## 6. Why does Loki index labels instead of the entire log content?

Indexing the complete content of every log line would be expensive and inefficient.

Loki indexes labels such as:

    service
    environment
    namespace

These labels help Loki narrow down the relevant log streams.

The actual log content can then be scanned and filtered.

Simple mental model:

> Labels tell Loki where to look, while log filters tell Loki what to look for.

---

## 7. What is low cardinality and why is it important?

Low-cardinality labels have a limited number of possible values.

Good examples:

    service
    environment
    namespace

High-cardinality values can have a large number of unique values.

Examples:

    user_id
    request_id
    timestamp

Using highly unique values as labels can create too many log streams and negatively affect Loki's performance.

---

## 8. What is the difference between structured and unstructured logs?

Unstructured logs are plain-text logs that are easy for humans to read, but extracting specific fields can be difficult.

Example:

    ERROR Payment failed for user 123

Structured logs use a consistent format, commonly JSON, where information is stored in separate fields.

Example:

    {
      "level": "ERROR",
      "user_id": "123",
      "message": "Payment failed"
    }

Structured logs are easier to parse, filter, and query.

---

## 9. What is LogQL?

LogQL is the query language used to query and filter logs stored in Grafana Loki.

A basic query using labels:

    {service="api-service"}

This selects log streams where the `service` label is `api-service`.

---

## 10. How do you filter log content using LogQL?

The `|=` operator filters log lines containing specific text.

Example:

    {service="api-service"} |= "ERROR"

This means:

> Show logs from `api-service` that contain the text `ERROR`.

---

## 11. How do you query structured JSON logs?

First, select the relevant log streams:

    {service="api-service"}

Then parse the log as JSON:

    {service="api-service"} | json

After parsing, filter using a field:

    {service="api-service"} | json | level="ERROR"

If `environment` is also a Loki label:

    {service="api-service", environment="production"} | json | level="ERROR"

This means:

1. Select logs from `api-service`.
2. Select only the `production` environment.
3. Parse the logs as JSON.
4. Show only logs where `level` is `ERROR`.

# Interview Questions

## Question 1: What is Grafana Loki, and how is it different from Prometheus?

**Answer:**

Grafana Loki is an open-source log aggregation system used to centrally collect, store, and query logs from applications and infrastructure.

Prometheus collects and stores metrics such as CPU usage, memory usage, request rate, latency, and error rate.

Loki stores logs, which provide detailed information about what actually happened inside the application, such as errors, exceptions, and application events.

> Prometheus → What is happening?

> Loki → What exactly happened?

---

## Question 2: What are labels and log streams in Loki?

**Answer:**

Labels are key-value pairs attached to log streams that help identify and organize logs.

A log stream is a collection of log entries that share the exact same set of labels.

---

## Question 3: Why does Loki index labels instead of the entire log content?

**Answer:**

Indexing the entire content of every log line would be expensive and inefficient.

Loki indexes labels such as `service`, `environment`, and `namespace` to quickly narrow down relevant log streams. The actual log content is then filtered after selecting those streams.

**Answer:**

Unstructured logs are plain-text logs that are easy for humans to read, but extracting specific information can be difficult.

Structured logs use a consistent format such as JSON, where information is stored in separate fields, making the logs easier to parse, filter, and query.

## Question 5: What is LogQL, and how would you find only ERROR logs from api-service running in production?

**Answer:**

LogQL is the query language used to query and filter logs stored in Loki.

If `service` and `environment` are labels and `level` is a JSON field:

    {service="api-service", environment="production"} | json | level="ERROR"

This:

1. Selects the `api-service` log streams.
2. Selects only the `production` environment.
3. Parses the logs as JSON.
4. Filters logs where the `level` field is `ERROR`.
