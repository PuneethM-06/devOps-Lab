# Interview.md — Day 82

## Must-Know Fundamentals

### 1. What is OpenTelemetry?

OpenTelemetry, also known as **OTel**, is an open-source observability framework and set of standards used to generate, collect, and export telemetry data.

It supports:

- Metrics
- Logs
- Traces

For distributed systems, OpenTelemetry can help trace a request as it travels across multiple services.

---

### 2. What problem does distributed tracing solve?

In a distributed application, a request may travel through multiple services.

    User
      ↓
    Frontend
      ↓
    API Service
      ↓
    Payment Service
      ↓
    Database

If the request is slow, metrics may tell us that the request took a long time, but they may not immediately show where the time was spent.

Distributed tracing helps answer:

- Which services handled the request?
- How long did each operation take?
- Which service or operation was slow?
- Where did an error occur?

---

### 3. What is a Trace?

A **Trace** represents the complete journey of a single request through one or more services.

Example:

    User
      ↓
    Frontend
      ↓
    API Service
      ↓
    Payment Service
      ↓
    Database

The entire journey is one trace.

---

### 4. What is a Span?

A **Span** represents an individual operation or unit of work within a trace.

Example:

    Trace: User Checkout

    ├── Frontend Span
    ├── API Span
    ├── Payment Span
    └── Database Span

Simple difference:

> **Trace = Complete request journey**

> **Span = Individual operation within that journey**

---

### 5. What is a Trace ID?

A **Trace ID** uniquely identifies the complete trace.

All spans belonging to the same request share the same Trace ID.

    Trace ID: abc123

    Frontend Span → Trace ID: abc123
    API Span      → Trace ID: abc123
    Payment Span  → Trace ID: abc123
    Database Span → Trace ID: abc123

---

### 6. What is a Span ID?

Each individual span has its own unique Span ID.

    Frontend → Span ID: 111
    API      → Span ID: 222
    Payment  → Span ID: 333
    Database → Span ID: 444

So:

> **Trace ID identifies the complete request journey.**

> **Span ID identifies an individual operation.**

---

### 7. What is a Parent Span ID?

A Parent Span ID connects spans together in a parent-child relationship.

Example:

    Frontend
    Trace ID: abc123
    Span ID: 111

            ↓

    API
    Trace ID: abc123
    Span ID: 222
    Parent Span ID: 111

The API span is linked to the Frontend span.

---

### 8. What is Context Propagation?

**Context propagation** is the process of passing trace context between services.

When Service A calls Service B:

    Service A
    Trace ID: abc123
    Span ID: 111
            ↓
       Trace Context
            ↓
    Service B
    Trace ID: abc123
    Span ID: 222
    Parent Span ID: 111

The next service:

1. Receives the trace context.
2. Keeps the same Trace ID.
3. Creates a new Span ID.
4. Links the new span to the previous span through the parent-child relationship.

This allows the complete request to remain connected as one trace.

---

### 9. What is Instrumentation?

Instrumentation is how telemetry data is generated from an application.

For tracing, instrumentation creates spans.

There are two main types:

#### Automatic Instrumentation

OpenTelemetry automatically creates spans for supported libraries, frameworks, and operations.

Examples:

- HTTP requests
- Database queries
- External HTTP calls
- Supported frameworks

#### Manual Instrumentation

Developers manually create spans for custom application operations.

Examples:

    processPayment()
    validateCart()
    sendConfirmation()

Simple difference:

> **Automatic instrumentation creates spans for supported operations automatically.**

> **Manual instrumentation requires developers to explicitly create spans for custom operations.**

---

### 10. What is the OpenTelemetry Architecture?

The basic architecture is:

    Application
        ↓
    Instrumentation
        ↓
    OTel SDK
        ↓
    OTel Collector
        ↓
    Tracing Backend

---

### 11. What does the OpenTelemetry SDK do?

The OpenTelemetry SDK runs inside the application.

It can:

- Create and manage spans
- Process telemetry
- Apply sampling
- Export telemetry

Simple definition:

> **The OTel SDK processes and exports telemetry generated by instrumentation inside the application.**

---

### 12. What does the OpenTelemetry Collector do?

The OpenTelemetry Collector receives telemetry from one or more applications.

It can:

- Receive telemetry
- Process telemetry
- Filter telemetry
- Transform telemetry
- Batch telemetry
- Export telemetry

Example:

    Application A ──┐
    Application B ──┼──→ OTel Collector
    Application C ──┘
                          ↓
                    Tracing Backend

Important:

> **The Collector is not the permanent storage backend.**

It acts as a telemetry pipeline between applications and observability backends.

---

### 13. What does the Tracing Backend do?

The tracing backend stores traces and allows them to be queried and visualized.

Examples:

- Jaeger
- Grafana Tempo

    OTel Collector
          ↓
    Tracing Backend
          ↓
    Store + Query + Visualize

---

### 14. How Does a Request Remain Connected Across Multiple Services?

Example:

    Frontend → API → Payment → Database

The request keeps the same Trace ID through context propagation.

    Trace ID: abc123

    Frontend
    Span ID: 111
        ↓

    API
    Span ID: 222
    Parent: 111
        ↓

    Payment
    Span ID: 333
    Parent: 222
        ↓

    Database
    Span ID: 444
    Parent: 333

The same Trace ID shows that all spans belong to the same request.

The parent-child relationships show how the spans are connected.

---

### 15. How Does Tracing Help Troubleshoot a Slow Request?

Suppose a request takes 5 seconds:

    Frontend        → 100ms
    API Service     → 200ms
    Payment Service → 4.5s
    Database        → 100ms

Tracing helps identify that the Payment Service is where most of the request time was spent.

We can then investigate further inside the Payment Service:

    Payment Service
    ├── Database query
    ├── External API call
    ├── Application logic
    └── Other operations

Tracing helps answer:

> **Where did this specific request become slow or fail?**

---

### 16. How Do Tracing and Metrics Work Together?

A practical troubleshooting flow:

    Slow Request Reported
            ↓
    Use Tracing
            ↓
    Identify slow service/span
            ↓
    Example: Payment Service → 4.5s
            ↓
    Use Metrics
            ↓
    Check whether many requests are affected
            ↓
    Check:
    - P50 / P95 / P99
    - Request Rate
    - Error Rate
    - CPU Usage
    - Memory Usage
    - Pod Replicas
    - Scaling
            ↓
    Identify Root Cause
            ↓
    Fix the Issue
            ↓
    Use Metrics + Traces
    to Verify Improvement

Simple mental model:

> **Tracing helps identify where a specific request went wrong or became slow.**

> **Metrics help determine how widespread the problem is and investigate overall system behavior.**

# Interview Questions

## Question 1

### What is OpenTelemetry, and what problem does distributed tracing solve?

**Answer:**

> OpenTelemetry is an open-source observability framework and set of standards used to generate, collect, and export telemetry such as metrics, logs, and traces. Distributed tracing helps track a specific request across multiple services and identify where the request becomes slow or fails.

---

## Question 2

### What is the difference between a Trace and a Span?

**Answer:**

> A Trace represents the complete journey of a single request, while a Span represents an individual operation or unit of work within that trace.

---

## Question 3

### How do multiple spans across different services remain connected as part of the same trace?

**Answer:**

> They remain connected through context propagation. The trace context is passed between services, allowing them to keep the same Trace ID while creating new spans connected through parent-child relationships.

---

## Question 4

### What is the difference between automatic and manual instrumentation?

**Answer:**

> Automatic instrumentation allows OpenTelemetry to automatically create spans for supported libraries and operations, such as HTTP requests and database calls. Manual instrumentation is when developers explicitly create spans for custom application operations.

---

## Question 5

### What is the difference between the OpenTelemetry SDK, OTel Collector, and tracing backend?

**Answer:**

> The OpenTelemetry SDK runs inside the application and processes telemetry generated by instrumentation. The OTel Collector receives telemetry from one or more applications and can process, filter, transform, batch, and export it. The tracing backend permanently stores the traces and allows them to be queried and visualized.
