# Day 94 — HashiCorp Vault and Dynamic Secrets

## 1. What is the difference between a static secret and a dynamic secret in HashiCorp Vault?

A static secret is an existing secret that is stored and retrieved when requested.

A dynamic secret is generated by HashiCorp Vault on demand. Dynamic credentials are managed using a lease and TTL, allowing them to expire, be renewed, or be revoked.

---

## 2. What is a Secrets Engine in HashiCorp Vault, and which Secrets Engine would you use to generate dynamic database credentials?

A Secrets Engine is a Vault component responsible for storing, generating, or managing a specific type of secret.

Different Secrets Engines are used for different use cases.

- KV Secrets Engine stores static key-value secrets.
- Database Secrets Engine generates and manages dynamic database credentials.
- PKI Secrets Engine generates and manages certificates.

To generate dynamic database credentials, the Database Secrets Engine is used.

---

## 3. Explain the difference between authentication and authorization in HashiCorp Vault.

Authentication verifies the identity of a user, application, or workload.

Authorization determines what that authenticated identity is allowed to do.

Vault uses policies to define what resources or secrets an authenticated identity can access.

An application can successfully authenticate to Vault but still be denied access if its policy does not allow the requested action.

---

## 4. What are a lease and TTL in HashiCorp Vault, and how do they help manage dynamic secrets?

TTL, or Time To Live, defines how long dynamically generated credentials are valid.

A lease is Vault's mechanism for tracking and managing the lifetime of those credentials.

A lease can be renewed to extend the lifetime of the credentials or revoked to invalidate them.

In simple terms:

- TTL = How long the credentials are valid
- Lease = How Vault manages and tracks their lifetime

---

## 5. Explain the complete flow of how an application gets dynamic database credentials from HashiCorp Vault.

The application first authenticates to HashiCorp Vault.

Vault verifies the application's identity and checks its policies to determine whether it is authorized to request database credentials.

If access is allowed, the request is handled by the Database Secrets Engine.

Vault uses its configured access to the database to dynamically create unique credentials based on the configured database role and permissions.

The generated username and password are returned to the application along with a lease and TTL.

The application uses the credentials to access the database.

The lease can be renewed if the credentials are still required, or the credentials can expire or be revoked when they are no longer valid.
